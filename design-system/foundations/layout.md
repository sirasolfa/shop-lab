# Layout — gap · spacing · grid `[F]`

> 출처 — Figma **Layout** `170:1666`, **Grid** `380:1802`

Layout 프레임 머리말(원문):

> 인터페이스 안에서 컴포넌트가 배치되는 간격과 여백을 통일하기 위한 토큰 세트입니다.
> 모든 gap·spacing 값은 primitive / unit 스케일을 참조하며, 화면 곳곳의 간격을 같은 리듬으로 유지하는 것이 목표입니다.

---

## 1. `layout.gap.*` — 요소와 요소 사이

시안 설명(원문):

> gap 토큰은 요소와 요소 사이 거리를 맞출 때만 사용한다. (카드 리스트, 폼 필드 그룹, 섹션 간 간격 등)
> 이름은 픽셀 값을 그대로 사용한다. 예: `layout.gap/16` = 16px.
> 값은 모두 primitive / unit 토큰(0, 2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 72, 80…)을 참조한다.

조사 중 실제로 확인된 `layout/gap/*` 변수 (이름 = px 값):

`0` · `2` · `4` · `6` · `8` · `12` · `16` · `20` · `24` · `32` · `40` · `48` · `64` · `72` · `80`

> 설명문에 열거된 목록에는 `6` 이 없지만, 변수 `layout/gap/6` = `6` 은 실제로 존재합니다(끝에 "…"가 붙어 있어 열거는 예시).

## 2. `layout.spacing.*` — 컴포넌트 안팎 여백

시안 설명(원문):

> spacing 토큰은 컴포넌트의 내부/외부 여백을 정의할 때 사용한다. (버튼 padding, 카드 내부 여백, 섹션 상단/하단 여백 등)
> 이름은 크기 단계로 표현한다. `3xs, 2xs, xs, md, lg, xl, 2xl, 3xl`. 각 단계는 primitive / unit 토큰을 참조한다.
> 예: 3xs = 8px, 2xs = 12px, xs = 16px, md = 20px, lg = 24px, xl = 32px, 2xl = 40px, 3xl = 48px.
> 컴포넌트 토큰에서 `*-padding-x/y`, `*-margin-top/bottom` 을 정의할 때 임의 숫자를 쓰지 않고 항상 `layout.spacing` 스케일 중 하나를 선택한다.
> 같은 역할의 컴포넌트(버튼 그룹, 카드, 섹션 등)는 가능한 한 동일한 spacing 단계만 사용해 레이아웃 리듬을 유지한다.

### ⚠️ 인쇄된 라벨과 실제 값이 다릅니다

| 토큰 | 시안에 인쇄된 라벨 | **변수 실제값 / 시안 막대 길이** | |
|---|---|---|---|
| `layout.spacing.3xs` | 8px | **8** | ✓ |
| `layout.spacing.2xs` | 12px | **12** | ✓ |
| `layout.spacing.xs` | 16px | **16** | ✓ |
| `layout.spacing.md` | 20px | **20** | ✓ |
| `layout.spacing.lg` | 24px | **24** | ✓ |
| `layout.spacing.xl` | 32px | **28** | ⚠️ |
| `layout.spacing.2xl` | 40px | **32** | ⚠️ |
| `layout.spacing.3xl` | 48px | **40** | ⚠️ |

검증 방법 — 시안 `186:2339` 안의 각 행은 `token 라벨` + `값에 바인딩된 막대` + `px 텍스트` 로 구성됩니다.
막대 높이(변수 바인딩)와 `get_variable_defs` 값은 **28 / 32 / 40** 으로 일치하고, 옆에 인쇄된 텍스트와
설명문만 **32 / 40 / 48** 입니다. **구현은 변수 실제값(28/32/40)을 따르는 것이 안전**합니다.

### 스케일에 `sm` 단계가 없습니다

`3xs → 2xs → xs → md → lg → xl → 2xl → 3xl`. `xs` 와 `md` 사이에 `sm` 이 비어 있습니다.
시안 설명문의 열거도 동일하게 `sm` 을 건너뜁니다(오기가 아니라 의도로 보이나 확인 필요).

## 3. `number/unit/*` — primitive 수치 스케일

`search_design_system` 으로 확인한 결과, 컬렉션 이름은 **`primitive`**, 경로는
`design_systems/NDS - NOVERA Design System/variables/primitive/float/number/unit/<N>` 입니다.

확인된 항목: `0` `1` `2` `4` `6` `8` `10` `12` `20` `32` `48` `56` `64` `96`
— 모두 **이름 = px 값**.

> `[?]` 일부 프레임에서 `number/unit/7` → `16`, `number/unit/14` → `40`, `number/unit/18` → `64`,
> `number/unit/21` → `104` 처럼 **이름과 값이 어긋나는** 참조가 관측됐습니다.
> 다른 라이브러리(인덱스 기반 unit 스케일)를 물고 있는 인스턴스로 보이며, 출처 확인이 필요합니다.

## 4. Grid / Breakpoint

Grid 프레임(`380:1802`)에 정의된 세 뷰포트입니다.

| 뷰포트 | 프레임 크기 | 적용 기준 (시안 원문) | 노드 |
|---|---|---|---|
| Desktop | `1440 × 960` | **1200px 이상** | `475:3708` |
| Tablet | `768 × 960` | **1200px 미만 768px 이상** | `475:3722` |
| Mobile | `375 × 812` | **375px 이하** | `475:3757` |

### `[?]` 컬럼/거터/마진은 이 문서로 확정할 수 없습니다

컬럼 수·거터·마진은 Figma **layout grid** 속성으로만 정의돼 있고, MCP(`get_metadata`,
`get_design_context`, `get_screenshot`) 어느 경로로도 값이 노출되지 않습니다.
시안에 텍스트로 적힌 주석도 없습니다. 디자인 파일에서 직접 확인해야 합니다.

또한 Tablet 구간이 `768–1199`인데 Mobile 표기가 "375px 이하"여서 **376–767 구간의 정의가 비어** 있습니다.
(실무상 Mobile 레이아웃이 그 구간을 덮는 것으로 보이나, 시안에 명시가 없습니다.)

컴포넌트 쪽에서는 뷰포트를 **베리언트 프로퍼티 `viewport=desktop | mobile`** 로 다룹니다
(Table 컴포넌트만 예외적으로 `viewport=desktop|mobile` + `columns` 조합). tablet 전용 베리언트는 없습니다.
