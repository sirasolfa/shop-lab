# LIVE MD 상세 페이지 연관 상품 노출 실험

| | |
|---|---|
| 대상 화면 | 상품 상세 페이지 (예: [`/products/567`](https://shop.novera.town/products/567) — 이한결 11.13 파자마 비디오콜) |
| 목적 | 같은 아티스트·같은 유형 상품으로의 유입을 만들어 LIVE MD 연계 매출과 교차 탐색을 올린다 |
| 상태 | 초안 — [남은 결정 사항](#9-남은-결정-사항) 확인 필요 |
| 작성일 | 2026-11-10 |

## 1. 요약

- LIVE MD는 한 아티스트가 **같은 회차에 여러 이벤트 상품을 동시에 판매**하는데, 상세 페이지에는 다른 상품으로 가는 길이 없다.
- 상세 페이지에 모듈 두 개를 넣는다.
  - **모듈 1 — 같은 아티스트의 다른 LIVE MD**: 구매 영역 바로 아래
  - **모듈 2 — LIVE MD 최신 상품**(1차 카테고리 기준 최신순): 상세 정보 하단
- 판매 중·판매 종료 상세 페이지 모두에 노출하고, 카드에는 판매 종료 상품도 함께 보여 준다.
- 두 모듈 모두 **기존 공개 API만으로 구현 가능**하다. 서버 작업은 필요 없다.
- 검증은 **현행 vs 기본 노출 2군 → 담기 직후 바텀시트 추가 여부 순차 실험**을 권장한다. 판정 지표는 **회차 내 교차 구매율** 하나로 고정하고, 모듈 클릭률은 선행·진단 지표로 본다.

## 2. 배경

### 2.1 현재 상태 (2026-11-10 기준 실제 데이터)

`shop-api.novera.town` 공개 API로 확인한 LIVE MD 카탈로그다.

| 항목 | 값 |
|---|---|
| LIVE MD 상품 수 | 108개 |
| 아티스트 수 | 22팀 |
| 판매 회차 수 (아티스트 × 이벤트 날짜) | 38회차 |
| 상품이 2개 이상 동시에 열린 회차 | 33회차 (87%) |
| 회차당 상품 수 | 평균 2.8개 (1개 5회, 2개 8회, 3개 15회, 4개 9회, 6개 1회) |
| 회차 내 상품 가격이 모두 같은 회차 | 38회차 전부 |
| 가격대 | 7,400원 ~ 57,600원 (중앙값 17,800원) |
| 현재 판매 중인 LIVE MD | 0개 (모두 응모 마감) |

이한결의 경우 11.13 회차에 4종(파자마 비디오콜, 할리갈리 게임, 부채 꾸미기, FAN SIGN)이 모두 17,800원으로 동시에 열렸고, 그 전 10.14 회차에 2종이 있었다.

그런데 현재 상세 페이지는 상단의 아티스트명 링크 말고는 다른 상품으로 가는 경로가 없다. 연관 상품, 추천, 같은 회차 상품 영역이 모두 없다.

### 2.2 팬덤 특성으로 본 문제

**① 팬은 쇼핑몰이 아니라 상품 하나로 들어온다.**
LIVE MD 구매자는 아티스트 공지, SNS, 팬 커뮤니티에 걸린 링크를 타고 특정 상품 상세로 바로 들어온다. 홈이나 카테고리를 거치지 않으므로, 상세 페이지가 알려 주지 않으면 같은 회차의 다른 이벤트가 있다는 사실 자체를 모를 수 있다. 이 유입에서는 상세 페이지가 사실상 유일한 진열대다.

**② 구매 동기는 상품이 아니라 아티스트다.**
팬이 사는 것은 "파자마 비디오콜"이 아니라 "한결과 만날 기회"다. 같은 아티스트의 다른 이벤트는 대체재가 아니라 **또 하나의 만날 기회**이므로, 일반 커머스의 유사 상품 추천보다 관련성이 훨씬 높다. 한 이벤트에 관심을 보인 팬은 나머지 이벤트의 가장 유력한 잠재 구매자다.

**③ 응모형 상품이라 여러 개를 사는 것이 자연스럽다.**
LIVE MD는 당첨자 수가 정해진 응모 상품이다(567번은 당첨자 10명, 중복 구매 가능, 최대 500개). 팬은 당첨 확률을 높이려 이미 여러 장을 산다. 이벤트마다 경험이 다르기 때문에(영상통화, 팬사인, 게임, 꾸미기) "전부 응모"하려는 수요도 있다. 회차 내 가격이 전부 같아 추가 구매의 심리적 장벽도 낮다.

**④ 무료배송 기준이 교차 구매와 맞물린다.**
11.13 회차는 상품가 17,800원, 배송비 4,000원, 무료배송 기준 89,000원이다. 정확히 5개를 담으면 무료배송이 된다. 여러 이벤트를 나눠 담을 이유가 이미 가격 구조에 들어 있는데, 화면이 그 선택지를 보여 주지 않고 있다.

**⑤ 판매 기간이 짧아 놓치면 끝이다.**
회차 판매 기간은 3~4일 수준이다(567번은 11/5 등록, 11/8 마감). 팬이 다른 이벤트를 마감 뒤에 알게 되면 그 매출은 회수할 수 없다. 발견을 팬의 탐색에 맡기기에는 기간이 너무 짧다.

**⑥ 글로벌 팬 대상이라 상세가 길다.**
안내문이 한·일·영 3개 국어로 반복되어 상세 영역이 길다. 하단에만 모듈을 두면 도달률이 낮을 가능성이 크다. 같은 아티스트 모듈을 구매 영역 바로 아래에 두려는 이유다.

**⑦ 종료된 상세 페이지는 막다른 길이다.**
마감 뒤에도 공유된 링크로 유입은 계속된다. 지금은 "품절" 버튼만 보이고 갈 곳이 없다. 이한결은 현재 6종이 모두 종료 상태다.

**⑧ 지난 이벤트 목록은 "다음에도 열린다"는 신호가 된다.**
22팀 중 13팀이 2회차 이상 진행했다. 종료된 이벤트를 함께 보여 주면 이 아티스트가 이벤트를 반복해서 연다는 것을 알릴 수 있고, 이번에 놓친 팬의 재방문 기대를 만든다. 판매 종료 상품을 카드에 포함하는 이유다.

### 2.3 주의할 점: 매출이 늘지 않고 나뉘기만 할 수 있다

팬의 예산이 정해져 있다면, 한 이벤트에 5장 넣던 팬이 여러 이벤트에 나눠 넣을 뿐 총액은 그대로일 수 있다. 이 경우 교차 구매율은 오르지만 매출은 늘지 않는다. 그래서 교차 구매율과 **구매자당 결제액**을 반드시 같이 본다([6. 지표](#6-지표)).

## 3. 가설

| | 가설 | 확인 지표 |
|---|---|---|
| H1 | 구매 영역 아래에 같은 아티스트의 다른 LIVE MD를 보여 주면, 같은 회차 안에서 2종 이상을 구매하는 구매자 비율이 오른다 | 회차 내 교차 구매율 |
| H2 | 교차 구매는 예산 재분배가 아니라 추가 지출로 이어진다 | 구매자당 결제액, 방문자당 매출 |
| H3 | 상세 하단의 LIVE MD 최신 상품 모듈은 다른 아티스트 이벤트로의 탐색을 만든다 | 모듈 2 클릭률, 타 아티스트 상세 조회율 |
| H4 | 판매 종료 상세 페이지에 모듈을 두면 이탈이 줄고 판매 중 상품으로 유입된다 | 종료 페이지 이탈률, 판매 중 상품 도달률 |
| H5 | 판매 종료 카드를 함께 보여도 원 상품 구매를 방해하지 않는다 | 원 상품 구매 전환율 (가드레일) |

H3는 팬이 여러 아티스트를 동시에 좋아한다는 전제에 기대는데, LIVE MD 팬덤에서 이 전제가 성립하는지는 아직 근거가 없다. 이번 실험에서 처음 확인하는 항목이다.

## 4. 노출 방안

### 4.1 검토한 위치

| 위치 | 장점 | 단점 | 채택 |
|---|---|---|---|
| **구매 영역 바로 아래** (옵션·구매 버튼 아래, 상품 정보 탭 위) | 구매 결정 시점에 보임. 도달률 높음 | 구매 버튼과 가까워 주의가 분산될 수 있음 | 1단계 — 모듈 1 |
| **상세 정보 하단** | 구매 흐름을 방해하지 않음 | 3개 국어 안내문 때문에 도달률이 낮음 | 1단계 — 모듈 2 |
| **장바구니 담기 직후 바텀시트** | 구매 의도가 가장 높은 순간. 담기 전환을 방해하지 않음 | 담은 사람에게만 보임. 판매 종료 페이지에는 적용 불가 | 2단계 변형군 |
| 옵션 영역 안 "다른 이벤트도 함께 담기" | 한 번에 여러 이벤트 담기 가능 | 상품마다 입력 정보 5개가 따로 필요해 구조 변경이 큼 | 후속 검토 |
| 장바구니 페이지 | 구현이 단순함 | 결제 직전이라 이탈 위험. 바로 구매 경로는 거치지 않음 | 후속 검토 |

### 4.2 모듈 1 — 같은 아티스트의 다른 LIVE MD

- **위치**: 구매 영역 바로 아래
- **제목**: `{아티스트명}의 다른 LIVE MD` (예: 한결의 다른 LIVE MD)
- **형태**: 가로 스크롤 카드. 모바일 기준 2.3장이 보여 더 있다는 것을 알 수 있게 한다
- **대상**: 같은 아티스트(`brand.id`)의 LIVE MD 상품. 현재 보고 있는 상품은 제외
- **정렬**: ① 판매 중(마감 임박순) → ② 판매 종료(최신순)
- **최대 개수**: 10개
- **카드 구성**: 썸네일, 이벤트명, 가격, 상태
  - 판매 중: `D-2` 또는 `오늘 마감` 배지
  - 판매 종료: `응모 종료` 배지, 썸네일을 흐리게 처리
- **이벤트명 표기**: 상품명이 `[11.13 할리갈리 게임] 이한결(LEE HAN GYUL) 1st Mini Album [NOISE] MEET & CALL EVENT`처럼 대괄호 안쪽만 다르다. 말줄임이 걸려도 **대괄호 부분은 반드시 전부 보이게** 한다
- **빈 상태**: 다른 상품이 없으면 모듈을 숨긴다 (단일 상품 회차 5개가 해당)

### 4.3 모듈 2 — LIVE MD 최신 상품

- **위치**: 상세 정보 하단 (배송/교환/반품 안내 뒤)
- **제목**: `LIVE MD 최신 이벤트`
- **형태**: 2열 그리드 또는 가로 스크롤 ([남은 결정 사항](#9-남은-결정-사항))
- **대상**: 1차 카테고리 LIVE MD(`PCTGY3`) 전체, 최신순
- **중복 제거 (제안)**: 같은 아티스트 상품은 제외한다. 최신순 그대로면 지금 567번 상세의 상위 4개가 모두 이한결 상품이라 모듈 1과 똑같은 목록이 된다
- **최대 개수**: 10개
- **카드 구성**: 모듈 1과 같되 아티스트명을 추가한다
- **알아 둘 점**: 한 회차가 3~4종씩 연속으로 등록되어 최신순에서는 한 아티스트가 카드 여러 장을 차지한다. 결과에서 쏠림이 보이면 "회차당 카드 1장"으로 묶는 안을 후속으로 검토한다

### 4.4 판매 종료 처리

- **판매 종료 상세 페이지**: 판매 중 페이지와 똑같이 두 모듈을 노출한다. 정렬 규칙상 판매 중 상품이 앞에 온다
- **판매 종료 카드**: 판매 중 페이지에도 함께 노출한다. 배지와 흐림 처리로 상태를 구분하고, 눌렀을 때는 종료된 상세 페이지로 이동한다
- **전부 종료된 경우**: 지금처럼 LIVE MD 전체가 마감된 시기에는 모듈이 종료 카드로만 채워진다. 이때 클릭이 막다른 길로 이어지지 않는지 가드레일로 본다

### 4.5 구현 범위 — 서버 작업 불필요

두 모듈 모두 이미 열려 있는 공개 API로 조회된다. 실제 호출로 확인했다.

| 모듈 | 요청 | 확인 결과 |
|---|---|---|
| 모듈 1 | `GET /v1/products?brandId={brand.id}` | `brandId=88` → 이한결 6종 반환 |
| 모듈 2 | `GET /v1/products?category=PCTGY3` | LIVE MD 108종, 최신순 반환 |

- 목록 응답에 `isSelling`, `saleEndDate`, `price`, `mainImageId`, `brand`, `badges`가 들어 있어 카드에 필요한 값이 모두 있다
- 판매 중 우선 정렬, 현재 상품 제외, 같은 아티스트 제외는 프런트에서 처리한다
- `category` 파라미터는 문서가 아니라 호출 결과로 확인한 것이다. 개발 착수 전 프런트 담당자 확인이 필요하다
- 어센트, 코스모시, 오메가엑스는 LIVE MD가 아닌 상품도 가지고 있다. `brandId`만으로 조회하면 일반 상품이 섞이므로 `category=PCTGY3`와 함께 걸거나 프런트에서 걸러야 한다

## 5. 실험 설계

### 5.1 검증 방식 판단

현재 상황은 이렇다.

- 사이트에 GA4와 Amplitude는 붙어 있지만 A/B 분기 도구는 보이지 않는다
- 서버 작업 없이 진행해야 한다
- 회차 판매 기간이 3~4일로 짧고, 아티스트·회차마다 가격(7,400~57,600원)과 상품 수(1~6개)가 크게 다르다
- 지금은 판매 중인 LIVE MD가 없다. 다음 회차가 열려야 실험을 시작할 수 있다

처음 논의한 안은 현행을 빼고 "상세 기본 노출 vs 담기 직후 노출"을 비교하는 것이었다. 검토 결과 **현행을 대조군으로 두는 2군 실험을 먼저 하고, 담기 직후 노출은 그다음에 얹는 순차 실험**을 권장한다. 이유는 세 가지다.

1. **현행이 없으면 "늘었는지"를 알 수 없다.** 회차 간 편차가 커서, 지난 회차와 비교하면 모듈 효과와 아티스트 차이를 구분할 수 없다. 이번 실험의 목표는 연계 매출 증가 여부 확인이므로 같은 시기의 현행군이 필요하다.
2. **두 노출 방식은 분모가 달라 직접 비교가 안 된다.** 기본 노출은 상세 방문자 전체가 보고, 담기 직후 노출은 담은 사람만 본다. 클릭률을 나란히 놓으면 담기 직후 쪽이 항상 높게 나온다.
3. **현행군은 추가 개발이 없다.** 지금 화면 그대로다. 군을 하나 더 만드는 비용이 들지 않는다.

담기 직후 바텀시트는 기본 노출을 대체하는 안이 아니라 **기본 노출 위에 추가하는 안**으로 2단계에서 검증한다. 이렇게 하면 두 군의 분모가 같아진다.

### 5.2 단계

| 단계 | 내용 | 군 구성 | 개발 |
|---|---|---|---|
| 0. 기준선 | 지난 회차의 교차 구매율, 구매자당 결제액, 상세 간 이동률을 뽑는다 | — | 없음 (데이터 추출) |
| 1. 효과 확인 | 모듈이 연계 구매를 늘리는가 | 현행 50% vs 모듈 1+2 기본 노출 50% | 프런트만 |
| 2. 노출 시점 | 담기 직후 노출을 더하면 더 늘어나는가 | 기본 노출 50% vs 기본 노출 + 담기 직후 바텀시트 50% | 프런트만 |

0단계는 다음 회차가 열리기 전인 지금 진행할 수 있다.

### 5.3 군 배정 — 서버 없이

- 첫 방문 때 브라우저에서 무작위로 군을 정해 쿠키에 저장하고, 이후 같은 값을 쓴다
- 군 값을 Amplitude 사용자 속성과 GA4 사용자 속성으로 보낸다
- 한계: 기기 단위 배정이라 같은 사람이 PC와 모바일에서 다른 군에 들어갈 수 있다. 구매는 로그인 계정으로 묶이므로, 분석 때 두 군에 모두 노출된 계정은 제외한다

### 5.4 대상과 기간

- **대상**: LIVE MD 상세 페이지 방문자 (판매 중·판매 종료 모두). 판정은 판매 중 상품 방문자 기준으로 하고, 판매 종료 페이지는 따로 본다
- **분석 단위**: 회차 안에서의 방문자·구매자. 팬이 주문을 나눠 넣을 수 있어 주문 단위가 아니라 **구매자 × 회차** 단위로 본다
- **기간**: 아래 표본 수를 채울 때까지 여러 회차를 합산한다. 최소 3팀 이상, 4회차 이상을 포함한다
- **조기 종료 금지**: 회차 중간에 결과를 보고 멈추지 않는다. 회차 단위로만 끊는다

### 5.5 필요 표본 (가정치)

기준선 값을 아직 모르므로 가정으로 계산했다. 유의수준 5%(양측), 검정력 80% 기준이며 0단계가 끝나면 다시 계산한다.

| 지표 | 기준 가정 | 감지하려는 변화 | 군당 필요 수 |
|---|---|---|---|
| 교차 구매율 (구매자 기준) | 20% | 25% (+5%p) | 구매자 약 1,090명 |
| 교차 구매율 (구매자 기준) | 20% | 30% (+10%p) | 구매자 약 290명 |
| 교차 탐색률 (방문자 기준) | 15% | 20% (+5%p) | 방문자 약 900명 |
| 교차 탐색률 (방문자 기준) | 10% | 15% (+5%p) | 방문자 약 680명 |

### 5.6 트래픽이 부족할 때

0단계에서 회차당 구매자 수가 적어 **8주 안에 군당 구매자 290명을 채우기 어렵다**고 나오면 군을 나누지 않는다. 전체에 적용하고 지난 회차와 비교하되, 다음 조건을 지킨다.

- 같은 아티스트의 직전 회차와 비교한다 (아티스트 차이 제거)
- 회차 내 상품 수가 같은 회차끼리 비교한다
- 결과는 "효과가 있었다"가 아니라 "방향이 맞는지" 수준으로만 해석한다

## 6. 지표

### 6.1 지표 구조

클릭률과 연계 구매를 둘 다 보되 역할을 나눈다. **출시 여부는 교차 구매율로 판정**하고, 클릭률은 **왜 그런 결과가 나왔는지 설명하는 지표**로 쓴다. 이렇게 나누는 이유는 다음과 같다.

- 모듈 클릭률은 현행군에는 모듈이 없어 값이 존재하지 않는다. 두 군을 비교하는 지표가 될 수 없다
- 클릭은 오르는데 구매는 안 오를 수 있다. 판정 지표가 둘이면 결과가 엇갈릴 때 결론을 내릴 수 없다
- 실험 목표가 연계 매출이므로 판정은 구매로 한다

### 6.2 판정 지표 (1개)

| 지표 | 정의 |
|---|---|
| **회차 내 교차 구매율** | 한 회차에서 LIVE MD를 구매한 사람 중, 그 회차 안에서 서로 다른 LIVE MD 상품을 2종 이상 구매한 사람의 비율 |

### 6.3 매출 확인 지표

교차 구매가 추가 매출인지, 재분배인지 가린다.

| 지표 | 정의 | 보는 이유 |
|---|---|---|
| 구매자당 결제액 | 회차 내 LIVE MD 결제액 합계 ÷ 구매자 수 | 교차 구매율만 오르고 이 값이 그대로면 재분배다 |
| 방문자당 LIVE MD 매출 | LIVE MD 결제액 합계 ÷ LIVE MD 상세 방문자 수 | 전환율 변화까지 포함한 최종 매출 효과 |
| 구매자당 구매 상품 종류 수 | 회차 내 서로 다른 LIVE MD 상품 수의 평균 | 교차 구매의 깊이 |
| 구매자당 구매 수량 | 회차 내 LIVE MD 총 수량의 평균 | 종류는 늘고 수량은 그대로인지 확인 |

### 6.4 선행 지표

구매보다 표본이 빨리 쌓이므로 방향을 먼저 확인한다.

| 지표 | 정의 | 비교 가능 여부 |
|---|---|---|
| 교차 탐색률 | LIVE MD 상세 방문자 중 같은 세션에서 다른 LIVE MD 상세를 본 비율 | 현행군과 비교 가능 |
| 교차 담기율 | LIVE MD 상세 방문자 중 서로 다른 LIVE MD 2종 이상을 장바구니에 담은 비율 | 현행군과 비교 가능 |

### 6.5 진단 지표 (실험군 안에서만)

모듈 설계를 고치는 데 쓴다.

| 지표 | 정의 |
|---|---|
| 모듈 도달률 | 상세 방문자 중 모듈이 화면에 들어온 비율 (모듈 1, 2 각각) |
| 모듈 클릭률 | 모듈이 보인 방문자 중 카드를 누른 비율 (모듈 1, 2 각각) |
| 카드 순서별 클릭 분포 | 몇 번째 카드가 눌리는지 |
| 판매 종료 카드 클릭 비중 | 전체 카드 클릭 중 판매 종료 카드의 비율 |
| 클릭 후 구매 전환율 | 카드를 눌러 도착한 상품을 구매한 비율 |
| 모듈 2 타 아티스트 구매율 | 모듈 2를 거쳐 다른 아티스트 상품을 구매한 비율 (H3 확인) |

### 6.6 가드레일 지표

하나라도 기준을 넘으면 출시하지 않고 원인을 먼저 확인한다.

| 지표 | 정의 | 기준 |
|---|---|---|
| 원 상품 구매 전환율 | 처음 들어온 상품을 구매한 방문자 비율 | 현행군 대비 상대 5% 넘게 하락하지 않을 것 |
| 원 상품 담기율 | 처음 들어온 상품을 장바구니에 담거나 바로 구매를 누른 비율 | 현행군 대비 상대 5% 넘게 하락하지 않을 것 |
| 구매자당 결제액 | 6.3과 같음 | 현행군보다 낮지 않을 것 |
| 결제 완료율 | 주문서 진입 대비 결제 완료 비율 | 현행군 대비 하락하지 않을 것 |
| 판매 종료 카드 클릭 후 이탈률 | 판매 종료 카드를 누른 뒤 바로 나간 세션 비율 | 판매 중 카드 클릭 후 이탈률의 1.5배 이내 |
| 주문 취소·문의 건수 | 주문 1,000건당 취소 요청과 "잘못 응모" 유형 문의 건수 | 현행군 대비 늘지 않을 것 |
| 페이지 성능 | 상세 페이지 LCP, CLS | LCP 악화 200ms 이내, CLS 0.1 이하 유지 |

주문 취소·문의를 보는 이유는 LIVE MD가 취소 불가 상품이기 때문이다. 이벤트 카드가 서로 비슷해 팬이 의도와 다른 이벤트에 응모하면 바로 고객 응대 문제가 된다.

### 6.7 판정 기준

| 결과 | 결정 |
|---|---|
| 교차 구매율이 유의하게 오르고, 구매자당 결제액이 오르거나 같고, 가드레일 통과 | 전체 적용 후 2단계 진행 |
| 교차 구매율은 올랐지만 구매자당 결제액이 그대로 | 재분배로 판단. 매출 효과는 없으나 가드레일을 통과하면 유지하고, 2단계에서 결제액을 판정 지표로 올린다 |
| 교차 탐색률만 오르고 구매는 변화 없음 | 발견은 되지만 구매로 못 넘어감. 응모 정보 재입력 등 구매 단계 마찰을 확인한다 |
| 가드레일 위반 | 적용하지 않음. 모듈 위치를 아래로 내리거나 판매 종료 카드를 빼고 다시 실험 |
| 모든 지표 변화 없음 | 모듈 도달률부터 확인. 도달률이 낮으면 위치 문제, 높으면 수요 문제 |

## 7. 이벤트 로깅

기존 GA4·Amplitude에 아래 이벤트를 추가한다.

| 이벤트 | 시점 | 속성 |
|---|---|---|
| `related_module_view` | 모듈이 화면에 50% 이상 들어왔을 때 (세션당 모듈별 1회) | `module`(artist/category), `source_product_id`, `source_is_selling`, `item_count`, `selling_item_count`, `variant` |
| `related_item_click` | 카드를 눌렀을 때 | 위 속성 + `target_product_id`, `target_brand_id`, `target_is_selling`, `rank`, `is_same_round` |
| `related_sheet_view` (2단계) | 담기 직후 바텀시트가 열렸을 때 | `source_product_id`, `item_count`, `variant` |

확인이 필요한 기존 이벤트:

- 상품 상세 조회, 장바구니 담기, 결제 완료 이벤트가 **상품 ID와 함께** 남고 있는지
- 결제 완료 이벤트에 주문 내 상품 목록과 금액이 들어 있는지

기존 이벤트가 부족하면 교차 구매율과 결제액은 주문 DB에서 군 정보(계정 기준)와 붙여서 계산한다.

## 8. 리스크

| 리스크 | 대응 |
|---|---|
| 판매 종료 카드가 많아 모듈이 "살 수 없는 상품 목록"처럼 보인다 | 판매 중 우선 정렬, 배지와 흐림 처리. 판매 종료 카드 클릭 비중과 이탈률로 확인 |
| 지금처럼 LIVE MD가 전부 마감된 시기에는 모듈이 종료 카드로만 채워진다 | 실험 판정은 판매 중 상품 방문자 기준으로만 한다. 전부 종료된 시기의 노출 방식은 [남은 결정 사항](#9-남은-결정-사항) |
| 구매 버튼 근처 모듈이 원 상품 구매를 방해한다 | 원 상품 전환율 가드레일. 위반 시 위치를 내린다 |
| 비슷한 카드 때문에 다른 이벤트에 잘못 응모한다 | 대괄호 이벤트명 전체 노출, 취소·문의 가드레일 |
| 상품마다 응모 정보 5개(이름, 생년월일, 전화번호, 카카오톡 ID, 이메일)를 다시 입력해야 해 교차 구매가 중간에 끊긴다 | 1단계에서 클릭 후 구매 전환율로 확인. 낮으면 직전 입력값 자동 채움을 후속 과제로 올린다 |
| 회차당 구매자가 적어 판정이 나지 않는다 | 0단계에서 먼저 확인하고 5.6의 대안으로 전환 |
| 모듈 2가 다른 아티스트로 팬을 보내 원 아티스트 매출이 줄어든다 | 원 상품 전환율 가드레일, 모듈 2 클릭 후 원 상품 복귀율 확인 |
